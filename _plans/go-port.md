# Convert markfluence to Go (mirroring mzcld)

## Context

`markfluence` is today a Python (uv + click + httpx2 + marko) CLI that publishes
markdown to Confluence. The goal is to **rewrite it in place** in Go, reusing the
conventions and dependency toolkit of `~/mozilla/mozcloud/tools/mzcld` so it feels
like a sibling Mozilla Go tool: cobra CLI, stdlib `net/http`, lipgloss `ui` output,
Makefile + golangci-lint + goreleaser + Homebrew. The outcome is a single static
binary `markfluence` with **full behavioral parity** (update / create / fix / info,
attachments, page-width, frontmatter write-back) and **semantic** — not
byte-identical — output equivalence with the Python converter.

This happens in two phases: the Go port lands *alongside* the Python one and is
validated by hand against it (phase 1), then the Python source is deleted and
`~/mozilla/markfluence` becomes a pure Go module repo (phase 2). See **Phasing**.

## Resolved decisions (from grilling)

- **Repo**: rewrite in place; module `github.com/mozilla/markfluence`, `go 1.25.x`.
- **Converter**: `yuin/goldmark` with a **custom AST renderer** that emits Confluence
  storage format directly (not regex-post-processing of HTML).
- **Fidelity**: semantic equivalence only (valid storage that renders the same);
  byte-for-byte match to Python/marko is **not** required. Verified in phase 1 by a
  `paritycheck` tool (semantic XML tree-compare of the Go vs Python regression
  outputs) plus manual Confluence testing — see **Phasing** and **Testing**.
- **Phasing**: land the Go port *alongside* the Python one (phase 1), validate by
  hand, then delete Python (phase 2). See the **Phasing** section.
- **Output format**: Confluence **storage format** (XHTML, `representation: storage`),
  exactly as today. **ADF is out of scope** — it is an unrelated JSON representation
  that would reshape the converter, the goldens, and the comparison entirely.
- **Scope**: full parity — all four commands + full client + page-width + frontmatter
  quoting/write-back + mtime-skip + multi-file/non-zero-exit.
- **Raw storage passthrough**: port the `_shield_storage` sentinel trick so authors
  keep pasting raw `<ac:.../>`/`<ri:.../>` inline (goldmark won't treat colon tags as
  raw HTML, same as marko).
- **Callouts**: use a third-party goldmark alerts/callout **parser** extension for
  block recognition; register our **own** renderer for its node to emit
  info/tip/note/warning macros.
- **Auth/config**: **drop `.env`**. Base URL comes from a `--url` persistent flag;
  credentials come from a single env var holding `username:token`, split on the first
  `:` → HTTP basic auth. No dotenv, no viper.
- **Frontmatter**: port the bespoke flat parser + `update_frontmatter_field` verbatim
  (custom quoting, inline-`#` comments, surgical single-line write-back). No YAML lib.
- **Output**: mirror mzcld's lipgloss `internal/ui` package (colored
  Header/Success/Warn/Error, errors→stderr, `NO_COLOR`/piped detection, single
  exit-1).
- **Build/dist**: full mzcld mirror — Makefile (build/install/lint/vet/fmt/test),
  golangci-lint v2.6.0, `.goreleaser.yaml` (CGO_ENABLED=0, darwin/linux × arm64/amd64),
  Homebrew formula.

## Phasing

The port lands in two phases so the Python implementation stays available as a
trusted baseline while the Go one is validated.

### Phase 1 — Go port alongside Python

- Build the **full, idiomatic Go port** — all four commands + client + converter +
  frontmatter + pagewidth + ui + build/dist — fully functional by the end of the phase.
- Stand up a **Go regression suite in idiomatic `testdata/`**
  (`internal/convert/testdata/regression/<case>/`). The input fixtures
  (`main.md`/siblings/`assets/`/`test.input`) are **duplicated** into that tree so the
  Go suite is self-contained per Go convention. Go goldens are `test.output`
  (a `ConfluencePage` JSON), (re)generated by
  `go test ./internal/convert -run TestRegression -update`. Because this is a
  *separate tree* from the Python `tests/regression/`, both keep the `test.output`
  name with no collision (and nothing ends in `.go`, which the toolchain would try to
  compile). The Go suite asserts **exact-string** equality against its own goldens to
  catch Go-vs-Go regressions while iterating.
- **Leave the Python tree untouched** — `src/markfluence/` and `tests/regression/`
  (with the existing pytest suite) remain as the reference. Both languages read their
  own copy of the corpus; the fixtures are kept static during phase 1.
- Build a standalone **`paritycheck` tool** (`tools/paritycheck`, run via
  `make parity`, excluded from goreleaser). Per case it matches the Python
  `tests/regression/<case>/test.output` against the Go
  `internal/convert/testdata/regression/<case>/test.output`:
  `attachments`/`broken`/`warnings` compared **exactly**; `html` compared
  **semantically** by parsing both as XML fragments with stdlib `encoding/xml` (sort
  attributes, normalize insignificant whitespace, tree-compare), with a
  normalized-string fallback if a fixture won't parse. `encoding/xml` is the right
  parser because storage format is XHTML — **not** HTML5 (`x/net/html` would mangle
  the CDATA / `ac:`/`ri:` / self-closing forms) and **not** ADF. It reports each case
  as identical / cosmetic-only / structural diff, printing the diff for structural
  cases.
- **Validation is manual**: run `go test ./...` (Go suite green) + `make parity`
  (eyeball structural diffs) + manual Confluence testing; iterate on the Go converter
  to close real (structural) gaps, ignoring cosmetic ones.

### Phase 2 — remove Python

Once the Go port is judged good enough:

- Delete `src/markfluence/`, `pyproject.toml`, `uv.lock`, `justfile`,
  `.python-version`, and the Python `tests/` (pytest runners + `regression_harness.py`
  + `generate_regression_goldens.py` + `tests/regression/`).
- Delete `tools/paritycheck` — its job is done once the Python baseline is gone.
- **Update `.gitignore`** to strip the Python entries (`.venv/`, `__pycache__/`,
  `*.pyc`, `.python-version`, uv/ruff/pytest caches, etc.).
- The Go `testdata/` regression suite becomes the **sole** conformance suite
  (exact-match against its goldens; `-update` to regenerate). Repo is pure Go.

`github.com/yuin/goldmark` (+ its GFM extension for tables/strikethrough/task-lists/

**no** godotenv, **no** oauth2/GCP stack (mzcld's cloud deps are irrelevant here —

## The converter (crux)

`MdToConfluence(md *frontmatter.MarkdownFile, baseURL, spaceKey string) (*ConfluencePage, error)`.
Two supporting types mirror the Python dataclasses, adjusted to Go idiom:

- **`ConfluencePage{HTML, Attachments, Broken, Warnings}`** — a json-tagged struct
  (the converter's result, replacing Python's `(html, dict)` tuple). No `ToJSON`
  method: callers `json.Marshal` it; the regression generator marshals with its own
  normalization (`<ROOT>` redaction, sorted keys, indent-2).
- **`frontmatter.MarkdownFile{Filename, Content, Frontmatter, Body}`** — a source file
  parsed once. Constructors `Parse(filename, content string) *MarkdownFile` and
  `ParseFile(path string) (*MarkdownFile, error)` (the file read replaces Python's
  `OSError`). `Frontmatter` (a `map[string]string`) stays an exported field so `fix`
  can read it raw; normalized access is via accessor methods `Title()`, `PageID()`,
  `Space()`, `Parent()` returning `""` for unset — `PageID`/`Space`/`Parent` treat
  missing/blank/`"null"` as unset (the coordinate sentinel), `Title` only missing/blank
  (`"null"` is a legal title). This unifies the `"null"`-is-unset semantics across the
  commands, matching the recent Python refactor.

`md.Body` (frontmatter already stripped) is what gets converted; `md.Filename` locates
sibling `.md` files and resolves image paths. Pipeline, re-expressed for goldmark:

1. **Shield** raw `ac:`/`ri:` via a per-doc colon-free sentinel derived from the source
   (port `_shield_storage`); unshield after rendering.
2. Parse with goldmark (`extension.GFM` + the callout parser extension), then render
   with a **custom `renderer.NodeRenderer`** that walks the AST and emits storage
   format. This subsumes several Python regex passes natively:
   - fenced code → `<ac:structured-macro name="code">` + CDATA (escape `]]>`); language
     from the fence info string.
   - **soft line breaks → space** (kills the `collapse_paragraph_newlines` dance; no
     `<pre>` stashing needed).
   - callout node (from the extension) → info/tip/note/warning macro
     (`NOTE→info, TIP→tip, IMPORTANT→note, WARNING/CAUTION→warning`).
   - images (`ast.Image`) → `<ac:image>`; local supported+existing → `ri:attachment`
     with the stable `assets/x.png`→`assets_x.png` filename, collected for upload;
     remote → `ri:url`; missing/unsupported → `IMAGE BROKEN:` text. Title JSON
     (`{"width","height","align","title"}`) parsed for extra attrs; invalid values →
     warnings; `alt` always native.
   - links (`ast.Link`): rewrite `#frag` (github-slug → confluence-slug) and
     `other.md#frag`; rewrite sibling `.md` links to
     `{baseURL}/wiki/spaces/{space}/pages/{id}/{title-slug}` (or `viewpage.action` when
     no space). Needs the sibling-file `page_id`/`title` map and heading anchor map —
     port `build_docs_page_map`, `build_headings_anchor_map`, `github_slug`,
     `confluence_slug` (Go `regexp` is RE2; use `\p{L}` etc. for Unicode `\w`, and
     rewrite Python lazy quantifiers into negated classes / walk-based logic).
   - `<!-- confluence-toc -->` → toc macro.
3. Unshield.

Order note: link/anchor rewriting reads sibling files (independent of the AST render),
so it runs against source/AST metadata, not post-HTML — cleaner than the Python
ordering constraint. Preserve the anchor-before-doclink dependency.

## Config / auth change

- `--url` (persistent flag, required) → base URL, `rstrip('/')`.
- `CONFLUENCE_AUTH` env = `username:token`; split on first `:`; empty/malformed →
  friendly `ui.Error` + exit 1 (replaces `from_env` validation). Basic auth header on
  every request.
- Client: one `*http.Client` (timeout 30s; 60s for writes, 120s for uploads via
  per-request context), `Accept: application/json`. Port each method 1:1 including
  `set_content_property` retry-once-with-1s-sleep, `sync_attachments` SHA-256 comment
  skip/update, `_links.next` pagination, v1 endpoints for attachment writes + `get_user`.

## Testing

**Unit tests.** Port the pytest suites to stdlib **table-driven** tests next to the
code: `frontmatter` (quoting/comment/round-trip/write-back + the `MarkdownFile`
accessor normalization), `pagewidth`, `convert` (images/macros/links/callouts/shield),
`info` rendering, smoke (`markfluence --help`, group help). Use `t.TempDir()` +
`os.WriteFile` for sibling-file fixtures, mirroring mzcld's `migration_test.go` style.

**Converter regression suite (`internal/convert/testdata/regression/`).** The
language-neutral corpus from the Python side is copied into idiomatic Go `testdata/`;
`regression_test.go` walks each case, runs `MdToConfluence`, applies the same
normalization the Python harness did (`<ROOT>` path redaction, sorted-key JSON), and
**exact-matches** the Go `test.output` golden. A `-update` flag regenerates the goldens
(`go test ./internal/convert -run TestRegression -update`, wrapped by
`make regen-regressions`). These Go goldens legitimately differ byte-wise from marko;
that's fine, because cross-implementation parity is checked separately (below), not by
this suite.

**Phase-1 parity (`paritycheck`).** Cross-implementation equivalence is *not* asserted
in CI; it's validated by hand with the `tools/paritycheck` tool (`make parity`), which
semantically diffs the Python vs Go regression outputs (see **Phasing**). The tool and
the Python corpus go away in phase 2.

Run everything via `make test` → `go test ./...`.

## Verification

1. `make build && ./bin/markfluence --help` and each `--help` subcommand (smoke).
2. `make test` — ported unit tests + the Go regression suite pass; `make lint` and
   `make vet` clean.
3. **Converter parity (phase 1)**: `make parity` runs `tools/paritycheck` over the whole
   regression corpus, semantically diffing every Go `test.output` against its Python
   counterpart; manually confirm every remaining difference is cosmetic
   (whitespace/attr order), not structural, and iterate on the converter until so.
4. **Live end-to-end** against a scratch Confluence page (needs `--url` +
   `CONFLUENCE_AUTH`): `markfluence create` a new page, confirm page_id/space/parent
   written back and page renders; edit + `markfluence update` (verify mtime-skip, then
   `--force`); `markfluence info` and `fix`; confirm an image attachment uploads once
   and is skipped on re-run (SHA-256), and that page width applies.

## Risks / watch-items

- **Callout extension coupling**: we depend on the extension's AST node type; if its API
  is awkward, fall back to hand-detecting `ast.Blockquote` first-line `[!TYPE]`.
- **RE2**: Python `re` lazy quantifiers/`\w`-unicode in slug/link/anchor code must be
  rewritten (no lazy match, ASCII `\w` by default).
- **Custom renderer coverage**: a from-scratch storage renderer must handle every GFM
  node (lists, tables, nested blockquotes, inline emphasis/code, HTML blocks); missing a
  node type silently drops content — the ported converter tests are the guard.
- **Content-property value compare**: keep the string `==` semantics for
  `set_content_property` idempotency.
- **`paritycheck` XML parsing**: storage format is XHTML, so `encoding/xml` fits, but a
  fixture with undeclared `ac:`/`ri:` prefixes, CDATA, or self-closing quirks could
  still fail to parse; the tool must fall back to normalized-string compare per case
  (and say so) rather than crash or silently skip. It's a manual-review aid, not a gate,
  so a noisy false-positive is acceptable; a silent skip is not.
- **Fixture drift in phase 1**: the corpus lives in two trees (Python `tests/regression/`
  and Go `internal/convert/testdata/regression/`). Keep the inputs static during phase 1;
  if a case's inputs must change, change both copies (or regenerate the Go copy from the
  Python one) so `paritycheck` compares like against like.
